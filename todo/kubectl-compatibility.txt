Kubectl Compatibility
=====================

Goal
Enable the use of `kubectl` to create, view, delete, and modify Tugboat resources.

Current evidence
- `tugboat-apiserver` implements Kubernetes-compatible discovery endpoints (`/api`, `/api/v1`, `/apis`, etc.).
- `Table` conversion is implemented for `kubectl get` in `tugboat-apiserver/src/data/list.rs`.
- `PATCH` (JSON Merge Patch) and `status` subresource updates are supported in `resource_handlers.rs`.
- Resource models include necessary metadata for `kubectl` compatibility.
- Label and field selectors are supported in `ListQuery`.

What to implement
- Implement Strategic Merge Patch for more complex patch scenarios if needed (currently JSON Merge Patch is used).
- Verify `kubectl describe` output and implement Table-based details or specific descriptive output if necessary.
- Verify `kubectl edit` functionality (it may rely on `GET` and `PUT` or `PATCH`).
- Map any Tugboat-specific resources to K8s-like names if necessary (e.g., ensure `ships` works for `v1.Ship`).
- Test authentication compatibility if using Bearer tokens or certificates.

Implementation surfaces
- `tugboat-apiserver/src/endpoints/discovery.rs`
- `tugboat-apiserver/src/endpoints/resource_handlers.rs`
- `tugboat-apiserver/src/endpoints/utils.rs`
- `tugboat-resource-store/src/serializer/`

Acceptance criteria
- ✓ `kubectl get ships` (or equivalent) lists resources with correct columns.
- ✓ `kubectl create -f ship.yaml` successfully creates a Ship.
- ✓ `kubectl delete ship <name>` removes the resource.
- ✓ `kubectl patch ship <name> -p '{"spec":{"image":"..."}}'` works.
- ☐ `kubectl describe ship <name>` shows detailed information.
- ☐ `kubectl edit ship <name>` allows interactive modification.
- ☐ Multi-resource apply/delete works as expected.
