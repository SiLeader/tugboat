Ship Modified Reconciliation
============================

Status: DONE (2026-03-31)

Goal
Implement real handling for Ship Modified watch events in the agent.

What was implemented
- Field mutability is now explicitly defined and enforced:
  - image, ship_class, network_class_ref, uefi, PVC volume refs → VM recreate (delete + re-add)
  - Materialized volumes (ConfigMap / Secret) → in-place refresh of host files via virtio-9p
  - Scheduling fields (node_name, tolerations, scheduler_name) → true no-op (excluded from fingerprints)
- Volume fingerprint split into pvc_volume_fingerprint and materialized_volume_fingerprint so
  recreate is not triggered unnecessarily for ConfigMap / Secret content changes.
- reconcile_recreate: calls reconcile_deleted then reconcile_added; safe to crash between the two
  because the next reconcile will find no runtime and fall through to reconcile_added.
- refresh_materialized_volumes: re-materializes ConfigMap / Secret files in place; sets
  MaterializedVolumesRefreshed condition on success.
- No-op path (spec and both volume fingerprints unchanged) still checks pending CSI volume
  expansions as before.
- Runtime-missing fallback still delegates to reconcile_added unchanged.
- All modifications are idempotent; repeated identical events are true no-ops.

Changed files
- tugboat-agent/src/reconciler/ops/mod.rs — split volume_claims_fingerprint into
  pvc_volume_fingerprint and materialized_volume_fingerprint; added 5 new fingerprint tests.
- tugboat-agent/src/reconciler/ops/modify.rs — rewrote reconcile_modified; added reconcile_recreate
  and refresh_materialized_volumes.
- tugboat-agent/src/reconciler/ops/add.rs — updated to compute and pass split fingerprints.
- tugboat-agent/src/runtime/inner/mod.rs — split volume_fingerprint field into two; updated
  Runtime struct and accessors.
- tugboat-agent/src/runtime/mod.rs — updated RuntimeOperator to expose split fingerprint methods.
- tugboat-agent/src/runtime/create.rs — updated RuntimeCreateRequest to carry split fingerprints.
