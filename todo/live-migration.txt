Live Migration (CSI-based Shared Storage)
=========================================

Goal
Allow a running Ship to move between nodes with minimal downtime by leveraging CSI-backed shared storage.

Current evidence
- Core migration logic is implemented in `tugboat-agent/src/reconciler/ops/migration.rs` and `tugboat-runtime`.
- `tugboat-runtime` and `tugboat-vm-runtime-interface` support `migrate` and `migration-status`.
- Migration preflight checks target CNI readiness, architecture labels, and reachable node IPs.
- Current storage policy: live migration only supports PVC-backed storage that advertises `ReadWriteMany` (RWX) on both the claim and backing PersistentVolume.
- Target-side prepare failures now mark migration as failed with an explicit "source remains authoritative" message.

What to implement
- (Fixed) Exclude any support for shared storage-less (block) migration; only focus on CSI shared storage paths.
- (Fixed) Ensure CSI plugins used support `ReadWriteMany` correctly for migration.
- (Fixed) Tighten rollback and recovery further for multi-node failure scenarios that involve agent crashes or long-lived partitions during migration.
- (Fixed) Optimize memory migration bandwidth and convergence for high-memory Ships.

Implementation surfaces
- `tugboat-agent/src/reconciler/ops/migration.rs`
- `tugboat-scheduler/src/` (to ensure shared storage availability on the target node)
- `tugboat-agent/src/csi.rs` (to ensure RWX checks are correctly enforced)

Acceptance criteria
- ✓ Changing the `target_node_name` of a running `Ship` triggers a live migration.
- ✓ Preflight checks reject any Ship using non-RWX volumes for migration.
- ✓ Migration successfully completes using CSI (RWX) backed storage without data loss.
- ✓ Success and failure states are visible through status updates.
- ✓ Failed migration leaves the Ship in a recoverable state on the source node.
- ✓ Stuck migrations time out and are automatically cancelled (Pending: 2 min, Migrating: 30 min).
- ✓ QEMU migration is cancelled on failure to prevent resource leaks.
- ✓ Scheduler rejects nodes for Ships with non-RWX volumes (StorageFit plugin).
- ✓ Per-ShipClass QEMU migration tuning (bandwidth, downtime limit, xbzrle cache).
