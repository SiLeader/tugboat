CSI Agent and Runtime Completion
================================

Goal
Refresh the node-side CSI todo so it reflects the code as it exists today and focuses only on the remaining agent/runtime work.

Current evidence
- `README.md` already documents that node-side support includes `Block`, `Filesystem`, `NodeStageVolume` / `NodeUnstageVolume`, `nodePublishSecretRef` / `nodeStageSecretRef`, persisted publish-state recovery, `fs_type`, and `volume_attributes`.
- `tugboat-agent/src/csi.rs` implements stage, publish, unpublish, and unstage flows, persists `PublishedVolume` state, and passes `fs_type` plus `volume_attributes` into CSI RPCs.
- `tugboat-agent/src/reconciler/volume.rs` resolves `node_publish_secret_ref` and `node_stage_secret_ref`, but still rejects `controller_publish_secret_ref`, `controller_expand_secret_ref`, and `node_expand_secret_ref`.
- `tugboat-agent/src/reconciler/ops/add.rs` attaches CSI volumes during create and recovers persisted volume state for already-running ships; `tugboat-agent/src/reconciler/ops/delete.rs` detaches published volumes during cleanup.
- `tugboat-vm-runtime-interface/src/run.rs` and `tugboat-runtime/src/execute/vm/qemu/mod.rs` expose block volumes as virtio disks and filesystem volumes as 9p shares to the guest.

What is still missing
- Improve recovery beyond the persisted JSON state if stronger self-healing is needed. Current recovery still assumes the persisted publish records are present and match the planned mounts.
- Decide whether live CSI attach/detach/resize during `Ship` updates should ever become in-place operations instead of today’s explicit recreate-required status path.
- Document the practical driver compatibility matrix for VM guests, especially the `Filesystem -> 9p` path and any driver assumptions around mount namespaces and guest access.
- If controller and node CSI services can live on different sockets in the target environment, split the current single-endpoint driver assumption into explicit controller/node endpoint configuration.

Implementation surfaces
- `tugboat-agent/src/csi.rs`
- `tugboat-agent/src/reconciler/volume.rs`
- `tugboat-agent/src/reconciler/ops/add.rs`
- `tugboat-agent/src/reconciler/ops/delete.rs`
- `tugboat-agent/src/reconciler/ops/modify.rs`
- `tugboat-vm-runtime-interface/src/run.rs`
- `tugboat-runtime/src/execute/vm/qemu/mod.rs`

Acceptance criteria
- CSI volumes can be resized on the node side when the driver advertises `NodeExpandVolume`.
- Drivers that depend on controller-provided publish context can be used without patching the agent by hand.
- Volume-related `Ship` updates are rejected with an explicit, CSI-aware recreate-required status path when they cannot be applied live.
- The todo stays aligned with reality: it should not describe node expansion or controller publish context support as missing anymore.
