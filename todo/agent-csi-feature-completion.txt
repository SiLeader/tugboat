CSI Agent and Runtime Completion
================================

Goal
Refresh the node-side CSI todo so it reflects the code as it exists today and focuses only on the remaining agent/runtime work.

Current evidence
- `README.md` already documents that node-side support includes `Block`, `Filesystem`, `NodeStageVolume` / `NodeUnstageVolume`, `nodePublishSecretRef` / `nodeStageSecretRef`, persisted publish-state recovery, `fs_type`, and `volume_attributes`.
- `tugboat-agent/src/csi.rs` implements the full ControllerPublish → NodeStage → NodePublish pipeline; `publish_context` returned by `ControllerPublishVolume` is passed through into both `NodeStageVolume` and `NodePublishVolume`. Unpublish reverses the sequence and calls `ControllerUnpublishVolume` when appropriate.
- `tugboat-agent/src/csi.rs` also implements `expand()`: it queries `NodeCapability::ExpandVolume` and calls `NodeExpandVolume` when the driver supports it.
- `tugboat-agent/src/csi.rs` now also queries `NodeGetVolumeStats` when the driver advertises `GetVolumeStats`, and `tugboat-agent/src/reconciler/ops/add.rs` writes the reported usage / health back onto both `PersistentVolumeStatus.conditions` and `PersistentVolumeClaimStatus.conditions`.
- `tugboat-agent/src/reconciler/volume.rs` resolves `controller_publish_secret_ref`, `controller_expand_secret_ref`, `node_publish_secret_ref`, `node_stage_secret_ref`, and `node_expand_secret_ref`.
- `tugboat-agent/src/reconciler/ops/add.rs` attaches CSI volumes during create and recovers persisted volume state for already-running ships. After a successful publish it calls `csi.expand()` when `PersistentVolumeStatus.node_expansion_required` is set, and updates both `PersistentVolumeStatus` and `PersistentVolumeClaimStatus` capacity/resize state on success.
- `tugboat-agent/src/reconciler/ops/delete.rs` detaches published volumes during cleanup.
- `tugboat-vm-runtime-interface/src/run.rs` and `tugboat-runtime/src/execute/vm/qemu/mod.rs` expose block volumes as virtio disks and filesystem volumes as 9p shares to the guest.

What is still missing
- `reconciler/ops/modify.rs` treats all volume-spec changes identically. A capacity-only increase that the driver supports in place could instead trigger the node-expansion path rather than forcing a full recreate.
- Improve recovery beyond the persisted JSON state if stronger self-healing is needed. Current recovery still assumes the persisted publish records are present and match the planned mounts.
- Decide whether live CSI attach/detach beyond resize should ever become in-place operations instead of today’s explicit recreate-required status path.
- Document the practical driver compatibility matrix for VM guests, especially the `Filesystem -> 9p` path and any driver assumptions around mount namespaces and guest access.
- If controller and node CSI services can live on different sockets in the target environment, split the current single-endpoint driver assumption into explicit controller/node endpoint configuration.

Acceptance criteria
- ✓ CSI volumes can be resized on the node side when the driver advertises `NodeExpandVolume` (`csi.rs` `expand()` implemented).
- ✓ Drivers that depend on controller-provided publish context can be used without patching the agent by hand (`controller_publish_secret_ref` resolved in `volume.rs`).
- ✓ Dynamically provisioned expandable volumes are accepted by the agent because `controller_expand_secret_ref` is no longer rejected during volume validation.
- ✓ After node-side resize completes, the agent updates both `PersistentVolumeStatus` and `PersistentVolumeClaimStatus` so capacity and `resize_pending` do not wait for the controller-manager's next reconcile.
- ✓ `NodeGetVolumeStats` is queried when available, and CSI-reported usage is surfaced onto both `PersistentVolume` and `PersistentVolumeClaim` conditions.
- ✓ CSI `VolumeCondition` responses are tracked on both `PersistentVolume` and `PersistentVolumeClaim` conditions instead of being dropped on the floor.
- ✓ Volume-related `Ship` updates are rejected with an explicit, CSI-aware recreate-required status path when they cannot be applied live (`reconciler/ops/modify.rs`).
- The todo stays aligned with reality: it should not describe node expansion, controller publish context support, `NodeGetVolumeStats` / `VolumeCondition` support, controller expand secret support, PVC resize status propagation, or the CSI-aware recreate-required path as missing anymore.
