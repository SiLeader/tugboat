RBAC and ServiceAccount
=======================

Goal
Add a real authentication and authorization layer so Tugboat can support multi-tenant or partially trusted deployments.

Current evidence
- README.md lists "RBAC / ServiceAccount" as unfinished.
- There are no ServiceAccount, Role, RoleBinding, ClusterRole, or ClusterRoleBinding resources in tugboat-resources/proto/.
- tugboat-apiserver/src/lib.rs wires HTTP and TLS but does not authenticate a caller or authorize a request.
- tugboat-apiserver/src/data/status.rs has commented-out unauthorized and forbidden status helpers, which suggests the API layer expected auth-related responses but never finished them.

What to implement
- Add core/v1 ServiceAccount and the necessary RBAC resource types, likely under an rbac API group.
- Define how callers authenticate: bearer tokens, mTLS subject mapping, or both.
- Add API server middleware that extracts caller identity and attaches it to the request context.
- Enforce authorization for create, list, watch, read, update, delete, and status-subresource operations.
- Decide how service account tokens are created, rotated, stored, and revoked.
- Provide a bootstrap path for cluster-admin access so a new cluster is operable.
- Update client and sample configuration if credentials must be supplied by tugboat-client, tugboat-cli, or component configs.

Implementation surfaces
- tugboat-resources/proto/
- tugboat-resources/build.rs
- tugboat-resources/src/manifests/mod.rs
- tugboat-resource-store/src/serializer/mod.rs
- tugboat-apiserver/src/lib.rs
- tugboat-apiserver/src/data/
- tugboat-apiserver/src/endpoints/
- tugboat-client/src/
- sample-configs/

Acceptance criteria
- Unauthenticated requests are rejected with 401 when auth is required.
- Authenticated but unauthorized requests are rejected with 403.
- Namespace-scoped and cluster-scoped RBAC decisions are both enforced.
- Watch and list endpoints are protected the same way as write operations.
- Tests cover at least one allowed path and one denied path for both user and service-account identities.
