Advanced CSI Storage Support
============================

Goal
Fully support CSI-based Block and Filesystem storage, including integration with major providers.

Current evidence
- `tugboat-agent/src/csi.rs` and `tugboat-csi-operator` implement the core CSI pipeline.
- `tugboat-controller-manager/src/pvc_provisioner.rs` and `pv_cleanup.rs` implement dynamic provisioning, binding, and cleanup based on `StorageClass`.
- `tugboat-agent` implements volume attachment/detachment and node-side expansion for both Block and Filesystem modes.
- QEMU-based block and filesystem (virtio-9p-pci) translation is implemented in `tugboat-runtime`.
- CSI controller-side and node-side expansion is supported.

What to implement
- Verify and document compatibility with major CSI providers: Longhorn, OpenEBS, Ceph (RBD and CephFS), and TopoLVM.
- Implement `virtio-fs` support (as a higher-performance alternative to `virtio-9p`) for Filesystem storage.
- Optimize the I/O path for Ceph and Longhorn (e.g., direct-path vs. host-mount).
- Support TopoLVM-specific logic if needed (e.g., node-local storage discovery and scheduling integration).

Implementation surfaces
- `tugboat-runtime/src/execute/vm/qemu/mod.rs`
- `tugboat-agent/src/csi.rs`
- `tugboat-csi-operator/src/`

Acceptance criteria
- ✓ Successful provisioning and attachment of volumes from CSI drivers.
- ✓ Filesystem mode volumes are correctly mounted within the VM guest via virtio-9p.
- ✓ Block mode volumes are visible as raw block devices within the VM guest.
- ✓ CSI-based volume expansion is functional.
- ☐ `virtio-fs` support is implemented and verified.
- ☐ Performance meets expectations for standard VM-based workloads with Ceph or Longhorn.
- ☐ (Optional) TopoLVM is verified functional for node-local storage.
