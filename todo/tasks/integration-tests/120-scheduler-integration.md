# スケジューラー結合テスト

## 概要

スケジューラーが未スケジュールの Ship を検出し、適切なノードに割り当てるフローを検証する。
API サーバー + スケジューラーの連携動作をテストする。

## 前提

- API サーバーとスケジューラーが起動していること
- テスト用 Node が登録されていること

## テストシナリオ

### シナリオ 1: 基本的なスケジューリング

1. Node `test-node-1` を作成し、allocatable リソース（CPU, メモリ）を設定
2. ShipClass を作成
3. `spec.nodeName` を未設定の Ship を作成
4. スケジューラーが Ship を検出するまで待機（ポーリング）
5. Ship の `spec.nodeName` が `test-node-1` に設定されることを確認

### シナリオ 2: 複数ノードでのスコアリング

1. Node `node-a`（リソース多）と `node-b`（リソース少）を作成
2. 未スケジュールの Ship を作成
3. LeastAllocated スコアリングにより `node-a` が選ばれることを確認

### シナリオ 3: Taint/Toleration によるフィルタリング

1. Node `tainted-node` に taint を設定
2. toleration なしの Ship を作成
3. tainted-node にスケジュールされないことを確認（別のノードがある場合はそちらに割り当て）

### シナリオ 4: スケジュール不可能な Ship

1. 全ノードのリソースを使い切った状態で Ship を作成
2. Ship がスケジュールされずに残ることを確認
3. ステータスに適切な condition が設定されることを確認

## 注意事項

- スケジューラーの動作確認にはポーリングまたは Watch が必要
- タイムアウトを設けてテストが無限に待機しないようにする

## 完了条件

- 基本スケジューリングフローがテストされていること
- フィルタリングとスコアリングの結果が検証されていること
- `cargo test` が通ること
