# バリデーションとエラーハンドリングの結合テスト

## 概要

API サーバーのリクエストバリデーションとエラーレスポンスが正しく動作することを検証する。
不正なリクエストに対して適切なエラーメッセージとステータスコードが返ることを確認する。

## テストシナリオ

### シナリオ 1: 不正な名前の拒否

1. `metadata.name` に不正な文字（大文字、スペース、特殊文字等）を含むリソースを作成
2. 400 Bad Request が返ることを確認
3. エラーメッセージに理由が含まれること

### シナリオ 2: 必須フィールドの欠落

1. `metadata` を含まないリクエストを送信
2. 適切なエラーレスポンスが返ることを確認

### シナリオ 3: 存在しない Namespace へのリソース作成

1. 存在しない Namespace 配下に Ship を作成
2. エラーが返ることを確認（404 または 400）

### シナリオ 4: 不正な JSON ボディ

1. 不正な JSON をリクエストボディとして送信
2. 400 Bad Request が返ることを確認

### シナリオ 5: URL 内のリソース名と body 内の名前の不一致

1. URL のリソース名と `metadata.name` が異なるリクエストを送信
2. エラーが返ることを確認

### シナリオ 6: クラスタスコープリソースへの namespace 指定

1. ShipClass（クラスタスコープ）に `metadata.namespace` を設定して作成
2. バリデーションエラーが返ることを確認

## 完了条件

- 各バリデーションパターンのテストが実装されていること
- エラーレスポンスの形式（ステータスコード、メッセージ）が検証されていること
- `cargo test` が通ること
