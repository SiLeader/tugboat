# Ship フルライフサイクルの E2E テスト

## 概要

Ship の作成からスケジューリング、ステータス更新、削除までの完全なライフサイクルを
複数コンポーネントの連携で検証するエンドツーエンドテスト。

## 前提

- API サーバー、スケジューラー、コントローラーマネージャーが起動していること
- テスト用 Node が登録されていること

## テストシナリオ

### シナリオ 1: Ship の完全ライフサイクル

1. Namespace を作成
2. ShipClass を作成
3. Node を作成し、allocatable リソースとステータスを設定
4. PV と PVC を作成（ストレージ付き Ship の場合）
5. Ship を作成（ShipClass、PVC を参照）
6. スケジューラーにより `spec.nodeName` が設定されるのを待つ
7. ステータスを Running 相当に更新（エージェントの代替）
8. Ship のステータスを確認
9. Ship を削除
10. 関連リソースの状態を確認

### シナリオ 2: Deployment による Ship ライフサイクル

1. Namespace、ShipClass、Node を作成
2. Deployment を作成
3. ReplicaSet が自動作成されることを確認
4. Ship が自動作成されることを確認
5. Ship がスケジュールされることを確認
6. Deployment の template を変更（ローリングアップデート）
7. 新しい ReplicaSet と Ship が作成されることを確認
8. 古い Ship が削除されることを確認
9. Deployment を削除し全リソースがクリーンアップされることを確認

### シナリオ 3: Fleet による複数 Ship の管理

1. Fleet を作成
2. 関連する Ship とネットワークリソースが作成されることを確認
3. Fleet を削除し全リソースがクリーンアップされることを確認

## 注意事項

- エージェントの VM 起動は含まない（QEMU 不要）
- コントロールプレーンコンポーネントの連携のみを検証
- 各ステップでタイムアウト付きポーリングを使用

## 完了条件

- 複数コンポーネントが連携する完全なライフサイクルテストが実装されていること
- `cargo test` が通ること（コントロールプレーンコンポーネントが起動している環境）
