ConfigMap / Secret Volume Live Reload
=====================================

Goal
Make projected `ConfigMap` / `Secret` filesystem volumes refresh automatically when the
referenced resources change, without requiring Ship recreation or a Ship spec update.

Current evidence
- `tugboat-agent` watches `Ship` resources filtered by `spec.nodeName=<node>` and does not
  currently watch `ConfigMap` or `Secret` resources.
- ConfigMap / Secret filesystem volumes are materialized on the host during Ship reconcile
  and reused by the runtime, but the data is only refreshed when the Ship is recreated or
  its spec changes.

Why this matters
- Projected config volumes are most useful when config rotation and secret rotation can be
  rolled out without deleting the workload.
- Without follow-up work, the new volume type is functional but behaves more like a boot-time
  projection than a continuously reconciled one.

What to implement
- Decide whether the agent should watch `ConfigMap` / `Secret` objects directly or build an
  index from Ship -> referenced projected volumes and trigger targeted requeues.
- Define safe behavior for running VMs when projected files change: in-place rewrite only,
  status condition + rematerialize, or an explicit restart/recreate workflow.
- Ensure updates are idempotent and do not break CSI volume recovery or existing Ship modify
  semantics.
- Add tests covering config updates, secret updates, deleted resources, and recovery after an
  agent restart.

Implementation surfaces
- tugboat-agent/src/reconciler/mod.rs
- tugboat-agent/src/reconciler/volume.rs
- tugboat-agent/src/reconciler/materialized_volume.rs
- tugboat-agent/src/reconciler/ops/modify.rs
- tugboat-client runtime watch/controller helpers
