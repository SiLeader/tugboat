CNI and Multi-node Networking
===========================

Goal
Enable multi-node cluster networking with CNI and support for multiple network definitions.

Current evidence
- `tugboat-agent/src/cni.rs` and `tugboat-cni-operator` support Bridge, Flannel, Portmap, and Loopback.
- `tugboat-agent` publishes node CNI plugin readiness into `Node.status.cniPlugins`.
- `tugboat-scheduler` uses a `NetworkFit` plugin for scheduling based on network readiness.
- `tugboat-controller-manager` updates `NetworkClass.status` and `ClusterNetworkClass.status`.
- Apiserver exposes `/status` subresources for network classes.
- QEMU-based `virtio-net` supports multiple NICs.

What is still missing
- Prove end-to-end multi-node Ship-to-Ship connectivity with Flannel in a real cluster.
- Evaluate whether Calico/Cilium or richer secondary-network semantics still need dedicated work after Flannel is fully verified.
- Implement live update behavior for network attachment changes (if restart-required or in-place flows are desired).
- Better documentation and integration tests for multi-node networking.

Implementation surfaces
- `tugboat-agent/src/cni.rs`
- `tugboat-agent/src/reconciler/network.rs`
- `tugboat-controller-manager/src/network_class_status.rs`
- `manifests/samples/`
- `docs/csi/` (Update networking documentation too)

Acceptance criteria
- ✓ `NetworkClass` / `ClusterNetworkClass` can express a backend choice via `cniPlugin`, and Flannel-specific settings can be persisted in the API.
- ✓ The agent can translate multiple `NetworkClass` references into multiple VM interfaces and emit either `bridge` or `flannel` CNI conflists.
- ✓ Nodes publish observed CNI plugin readiness via `Node.status.cniPlugins`.
- ✓ The scheduler ensures a `Ship` lands only on nodes that satisfy its required network setup.
- ✓ `NetworkClass` and `ClusterNetworkClass` status update with `readyNodes`.
- ☐ At least one major CNI plugin (Flannel) is proven functional across multiple nodes with actual Ship-to-Ship connectivity.
- ☐ Connectivity between Ships on different nodes is established and reliable.
